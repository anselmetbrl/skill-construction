## the pipeline — converged shape (audit each claim/proposals as you go)
chain:  seeds → dossiers → gists → relations → index  (+ egress companion)

    seeds      a list of links + an optional contextual prompt. i pre-curate manually.
               flag+skip accidental index-repos (awesome-lists); never rabbithole into them.
    fetch      github api for structured data; scrape website/wiki for the rest.
               OVER-CAPTURE (readme, manifests, tree-shape for lang-roles, langs, license,
               issues, activity…); judge nothing at fetch-time. full fetch, minimal md store.
               retry ladder: plain → stealth → alternative → flag; never silently skip.
               immutability: raw dossiers persist; later layers compile, never rewrite.
    gist       the AGENT reads and writes gists ITSELF — no sub-LLM delegation (beware of agentic exportation of respons-ability).
               uni pass (from the repo alone), then multi pass (re-read each from the
               evolved whole). ground with quotes, not fabulation. #void, don't hallucinate.
               flag marketing-hype / paywall-sabotage / abandonment — impartially.
    tag        facets = a fixed list i give = categorical tags. 4 per repo, 12 across the
               collection, derived AFTER each&every repo is tagged. the root-vocabulary is
               inspiration, NOT a whitelist to stupefyingly conform to.
    relate     discovered flags only (conflicts-with, alternative-to) carrying the quote
               that shows them; "no relation" is a valid outcome.
    index      standalone nested tree, markdown fold, no leaderboard (just ranking for relevance for the prioritisation of attention), each repo once under its primary tag, blocked repos stay visible. it must not force me to open other files to understand a repo.
    egress     a post-scriptum companion that helps me DIGEST the index (its inter/trans
               relativity) — not a second index, not a self-audit.
