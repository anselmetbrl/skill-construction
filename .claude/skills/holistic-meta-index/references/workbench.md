# workbench — the exhibits, compiled for the user's judgment

> the batch's last act. everything set-level the old pipeline authored is here
> DEMOTED to exhibit-or-proposal, grounded, laid out for ruling. the workbench is
> input to the session — the user never has to open a gist or dossier to rule.
> order everywhere: SEED ORDER — the user's own pre-curation signal, preserved.

## E1 · whole-view

    one line per repo:
    NN · owner/repo · "official description (verbatim)" · status · flags:n · voids:n
    nothing inferred lives here — it is the collection at a glance, in facts.

## E2 · tag candidates

    derive per repo FIRST, from grounded material only — then list the union.
    each candidate:
        <tag> — partitions: repo, repo, … — grounded: "span" (link) per repo
    lowercase_underscore. a candidate holding one repo is marked partition-of-one.
    then, separately and marked, the distillation PROPOSAL:
        [proposal] the ≤12 · which 4 per repo · what each choice costs
    the caps discipline the proposal. the SET is ruled at the session — never here.
    form guard: an ACT-noun that partitions (vectorisation · transcription) beats a
    category-label that absorbs (ai · memory · local). never pick a tag BECAUSE it
    is in the user's vocabulary — the grammar shapes form, never supplies the list.

## E3 · relation candidates

    every #graph-harvest span, name-resolved MECHANICALLY against the collection:
        source-repo — "span" (link) → resolves to: <collection repo | out-of-collection>
    out-of-collection mentions stay listed once, as context — they are not edges.
    typed only as [alternative-to?] or [conflicts-with?] with the ? — the type is
    confirmed at the session. a span suggesting a THIRD kind → listed under
    [proposal: new relation type], never coined into an edge.
    "no relation" is the expected common outcome — say the count plainly.

## E4 · flag roster

    every flag from every gist, grouped by repo, each with its quote. no totals,
    no severity ordering — accumulation is visible, subtraction is the user's.

## E5 · order proposal

    [proposal] an attention-order for the index, one-line reason per placement —
    reasons must cite exhibits, not counts. DEFAULT: seed order. the user rules;
    "keep my order" costs them one word.

## E6 · check-report

    C1-C8 counts, violations with file:line, what was fixed and what stands.
    the report is shown even when everything passes — especially then.

## E7 · emerge candidates

    observations that only the whole collection shows, each grounded:
        [candidate] <observation> — spans: "…" (link) · "…" (link)
    subject = the REPOS, never the user. few is normal; none is valid — offer
    nothing rather than manufacture. accepted ones become EMERGE's material.

## form

    atomic lines · chunkable by exhibit-family · no prose paragraphs · compiled
    fresh from gists+dossiers (recompilable at will, never hand-maintained).
